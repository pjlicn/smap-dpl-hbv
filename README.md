## Purpose and scope

This package accompanies the paper and provides the core implementations of
the SMAP-adapted differentiable HBV model (δHBV), its LSTM parameter generator,
and the LSTM surrogate components. It includes training and testing entry
points and processed geographic static attributes for 891 study locations.

The code and documentation support understanding and reuse of the methods
with user-supplied dynamic inputs. See **External data** for input requirements
and **Example commands** for the training, testing, and verification commands.

## Model implementation

The dPL LSTM receives six atmospheric variables plus eight geographic static
attributes. It generates time-varying, bounded parameters for 16 parallel HBV
components. In the primary configuration, BETA, K0, and BETAET are dynamic;
other parameters use the final parameter time step. The SMAP-tailored HBV
normalizes soil-water storage by field capacity and applies a learned linear
correction:

```text
SM_HBV = clamp((SM / FC - b_LC) * a_LC, 0, 1)
```

The corrected soil-moisture values are averaged over the 16 components. The
direct-HBV implementation also calculates Q0, Q1, Q2, actual ET, and SWE.

This implementation builds on hydroDL/δHBV and adds
the SMAP-specific soil-moisture output and linear-correction parameters. The
surrogate implementation replaces direct HBV soil-moisture evaluation with an
LSTM_SURR approximation while retaining differentiability with respect to the
HBV parameters generated by LSTM_dPL.

The generic implementation retains routing-capable interfaces for compatibility.
For the soil-moisture study configuration, runoff routing is
disabled (`routing=False`, `routOpt=False`, and `comprout=False`) because runoff
simulation is outside the study scope.

## Primary entry scripts

- `code/train/train_smap_dpl_hbv.py`: training entry point with configurable
  input paths, output directory, GPU, and random seed.
- `code/test/test_smap_dpl_hbv.py`: testing entry point for a trained model and
  its matching normalization file.

The reusable model components are under `code/model/`, including the direct
δHBV implementation, LSTM parameter generator, and surrogate model classes.

## Directory structure

```text
code/            primary scripts, model implementation, utilities, and config
data/            processed static attributes and selected spatial identifiers
scripts/         example commands and package verifier
documentation/   code, data, source, traceability, and verification notes
citation/        BibTeX and RIS citations
```

## Inputs and outputs

LSTM_dPL input order:

```text
APCP, DLWRF, DSWRF, PRES, SPFH, TMP,
Albedo, Capa, landcover, NDVI, T_BULK_DEN, T_CLAY, T_SAND, T_SILT
```

Direct HBV forcing order:

```text
APCP, TMP, PET
```

Target used by the primary training script: `SMAP_AM`.

Direct model output order:

```text
corrected soil moisture, Q0, Q1, Q2, actual ET, SWE
```

The test wrapper requests five CSV outputs (`out0` through `out4`) and evaluates
corrected soil moisture from `out0`.

## Experiment timing and sequence settings

- Source period: 2015-04-01 through 2020-03-31 (1,827 daily steps).
- Training period: 2015-04-01 through 2018-03-30.
- Test period: 2018-04-01 through 2020-03-31.
- Loss-bearing sequence length: 365 days.
- Training warm-up: 365 preceding days.
- Hidden size: 256; HBV components: 16; random seed: 111111.

## Software environment

Create the pinned reference environment with:

```bash
conda env create -f environment.yml
conda activate smap-dpl-hbv-reference
```

The custom LSTM execution path uses CUDNN and therefore requires a compatible
CUDA-enabled PyTorch installation for training. CPU-only environments support
syntax checking, data inspection, and model construction, but not the custom
CUDNN forward calculation.

## External data

Users must independently obtain and prepare:

- NLDAS-2 hourly primary forcing for APCP, DLWRF, DSWRF, PRES, SPFH, TMP, and
  PEVAP;
- the SMAP soil-moisture product corresponding to the study period;
- the combined 891-location dynamic NPZ expected by the public wrappers;
- a checkpoint and matching normalization JSON for testing.

See `documentation/SOURCE_DATA_AND_LICENSES.md` for the NLDAS and SMAP
product identifiers and source information. Prepare the dynamic inputs using
the schema in `documentation/DATA_DICTIONARY.md`.

## Included static attributes

`data/static_attributes/processed_static_attributes.nc` contains the original
processed 891-by-8 `float64` values in model order. Selected grid identifiers
and coordinates are included in the NetCDF and in
`data/spatial_indices/selected_locations.csv`. Values are stored without
normalization.

Field-level metadata are provided in `documentation/DATA_DICTIONARY.md` and
`data/metadata/static_attribute_metadata.csv`. The extraction utility in
`code/utils/extract_static_attributes.py` preserves the original processed
values, location identifiers, and ordering.

## Example commands

Inspect arguments:

```bash
python code/train/train_smap_dpl_hbv.py --help
python code/test/test_smap_dpl_hbv.py --help
```

Set the input and output paths in the example scripts before running them.

Training:

```bash
bash scripts/run_train_example.sh
```

Testing requires a user-provided experiment directory containing
`model_Ep_coeff<EPOCH>.pt` and `dapengscaler_stat.json`:

```bash
bash scripts/run_test_example.sh
```

Expected training products are the scaler JSON, epoch state dictionaries, and
`run.csv`. Expected test products are `out0`–`out4` CSV files and printed
evaluation summaries.

Verify the archive itself:

```bash
python scripts/verify_package.py
```

## Usage requirements

- Training uses the dynamic NPZ and PET inputs described above.
- The custom LSTM forward path requires compatible CUDA/CUDNN support.
- Testing uses a trained checkpoint and the matching
  `dapengscaler_stat.json` from the same experiment.
